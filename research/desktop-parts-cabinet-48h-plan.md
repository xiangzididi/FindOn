# 桌面智能二维抽屉阵列式零件柜：方案与 48h Demo 实施清单

日期：2026-10-01。设计草案，尚未完成实物验证。

## 1. 产品目标与实施前提

用户说出零件名称，系统找到对应编号的零件盒，自动取出并送到固定取物口；用户拿取或补充零件后，系统将盒子送回原柜格，并记录任务结果。

48h 以“六格柜、一盒在外、原位归还、取放闭环”为目标。暂按四人团队、有基础电子模块和快速加工条件设计；如果零件需要远程采购或从零加工全部运动结构，48h 风险明显增加，应优先复用现成模组。

- 柜体：2 行 × 3 列；首个可运行版本为 2 × 2，仍能证明二维寻址。
- 盒子：统一尺寸、统一取放接口、每盒一个零件品类，固定柜格。
- 起始打样参考：盒体宽 80 × 深 100 × 高 50 mm；单盒含零件质量目标不超过 200 g。这是限制设计范围的建议值，不是承载认证。
- 取物方式：盒子停在机器人托盘上，用户取出零件或补充零件，然后点击/说“放回当前盒”。首版不要求用户搬走整个盒子。
- 一次只允许一个盒子处于取出状态；它回柜前拒绝下一次取盒请求，并说明当前盒号。
- 不自动判断零件数量。盒子在库与零件剩余数量分别管理，数量若加入则由用户确认。

价值表达：把“记住位置、寻找零件、搬取盒子、归位”变成“说出名称、在固定窗口取用”。准确选择与可靠归位共同构成演示价值。

## 2. 机械方案

### 2.1 机构组成

| 子系统 | 建议方案 | 关键约束 |
|---|---|---|
| X 左右定位 | 步进电机 + 同步带 + 直线导轨，带动竖直模组 | 滑轨只负责导向，必须另有同步带或丝杆驱动 |
| Z 上下定位 | 步进电机 + 丝杆螺母 + 独立导轨，带动托盘 | 丝杆负责驱动，导轨承担偏载；按托盘、伸缩机构、盒子总质量选型 |
| E 前后取放 | 短行程线性模组，推动可伸缩拉钩和推板 | 有效行程必须覆盖盒子从柜内到完全离柜所需位移 |
| 拉钩开合 | 小舵机旋转钩爪，配盒子前部标准拉环 | 舵机仅开合钩爪，盒子重量由托盘承受 |
| 运输承托 | 固定在 Z 滑台上的托盘 | 托盘要托住整个盒底，带侧向限位及防滑出挡边 |
| 柜格 | 固定搁板、侧导向、入口倒角、末端止挡 | 盒子必须能完全抽离；普通抽屉的防脱扣需提前处理 |
| 取物口 | 阵列旁边、用户易触及的固定位置 | 托盘直接停靠，且取物口处于 X/Z 行程内 |

空间关系：柜体在后，X/Z 机构在柜体前方，E 轴沿柜体深度伸缩。前方必须预留盒子完整退出及随托盘移动的空间。柜体宽高不能直接当成整机外形尺寸，还要加取物口、模组和维护余量。

示意：

```text
正视图（柜格在后，移动托盘在前）
┌────────┬────────┬────────┐
│ S04/B04│ S05/B05│ S06/B06│
├────────┼────────┼────────┤
│ S01/B01│ S02/B02│ S03/B03│   [固定取物口]
└────────┴────────┴────────┘
             X 左右 / Z 上下

侧视图
后方 [柜格内的盒子] ← E 推回 / E 拉出 → [承托托盘] 前方
```

### 2.2 最先验证的结构细节

1. **标准接口**：每个盒子前方安装同样高度的拉环或卡槽；拉钩带导入斜面和少量装配调整余量。必须同时设计拉出与推回的受力面。
2. **连续支撑**：盒子从搁板滑到托盘时，底面始终有支撑。缩小柜体与托盘的间隙，用短过渡舌片/倒角避免盒底前缘卡住；应实测双向过渡。
3. **完全离柜后移动**：E 收回到运输位，盒子后缘已离开柜格与立柱，才能允许 X/Z 运动。不能只检测到盒子前端就认为已取出。
4. **推回后可靠脱钩**：推板把盒子推到标定深度，盒子由柜格的轻阻尼定位结构保持；钩爪打开后空载退回，不得把盒子再次拖出。
5. **稳定性与重心**：前伸托盘会形成倾覆力矩，底座固定或配重；Z 机构考虑失电下滑，不能默认任意丝杆都有自锁能力。

首选机械钩爪与承托托盘。磁吸方案只有在已经验证拉力、对位和释放机构时采用，否则“吸住容易、释放困难”会增加联调工作。

### 2.3 尺寸与标定

使用 S01 等柜格 ID、B01 等盒 ID，避免将固定位置和可移动物体混为同一个编号。

规则阵列初值：

```text
x = x0 + column × pitch_x + correction_x[slot]
z = z0 + row    × pitch_z + correction_z[slot]
```

行列从 0 开始。允许每格独立微调，实际制造偏差不应依赖全局间距公式消除。配置还包括 E 运输位、各格对接深度、取物口位置、速度和加速度上限。

盒子行程、托盘长度、拉钩长度先通过单格样机确定，再冻结柜格间距。不要先加工整柜再修改取放接口。

## 3. 硬件与控制

### 3.1 首版物料清单

| 物料 | 数量 | 选择依据 |
|---|---:|---|
| 统一零件盒 | 4–6 | 滑动顺畅、无不可移除防脱结构 |
| 柜架、搁板、底座 | 1 套 | 刚度、导向一致性和固定能力 |
| X 同步带直线模组 | 1 | 行程覆盖所有列和取物口 |
| Z 丝杆直线模组 | 1 | 行程覆盖所有行及取物口高度，承载按整个移动总成计算 |
| E 短行程线性模组 | 1 | 行程按完整抽盒距离验证 |
| 步进电机及驱动 | 通常各 3 | 优先模组配套；电流、电压、转速转矩需匹配 |
| 拉钩舵机、推板、托盘 | 各 1 | 舵机只承担钩爪动作，拉推负载由 E 轴承担 |
| ESP32 或团队熟悉的 MCU | 1 | USB 串口通信，有足够电机/限位/传感器接口 |
| 轴回零开关 | 每轴至少 1 | 推荐另加另一端限位；布线和消抖须验证 |
| 托盘盒子到位传感器 | 1 | 安装位置应能区分完全到托盘与刚进入托盘 |
| 对接确认传感器 | 1 | 可装在取件器上，验证盒子是否推到最终位置 |
| 实体急停、取物确认按钮 | 各 1 | 急停直接作用于运动使能/电源回路，不能依赖网页 |
| 电机电源、逻辑/舵机稳压电源 | 1 套 | 按实际驱动需求核算并留余量；舵机不要直接依赖主控小电源 |
| 笔记本、麦克风、USB 线 | 1 套 | 运行界面、后端、语音识别，减少嵌入式端工作量 |

不在模组未确定前给出精确采购价格或电机转矩。先确认库存、额定载荷和拉出阻力，再确定型号；“NEMA17/42 步进”只说明安装尺寸类别，不能单独说明承载能力。

若使用 DRV8825，按实际板卡资料设置限流并处理散热、近端去耦。Pololu 官方载板资料给出供电范围及其载板的散热条件；兼容板的采样电阻可能不同，不能直接照搬 VREF 换算。[官方资料](https://www.pololu.com/product/2133/)

### 3.2 控制分工

- **PC 后端**：零件查询、盒格映射、任务互斥、日志、界面同步、语音意图校验。
- **MCU**：步进脉冲、加减速、回零、限位、传感器、动作顺序和运行互锁。
- **通信**：优先 USB 串口，按行传输小型 JSON。48h 首版无需增加 Wi-Fi/MQTT 依赖。
- **运动代码**：采用团队已有、验证过的运动驱动或库，动作状态机非阻塞，持续响应急停及限位。
- **可替代方案**：若已有调通的 CNC 控制板与 Grbl，复用其运动能力，另解决舵机和传感器编排；不要同时新开发两套固件。

Grbl 的命令 `ok` 不代表物理运动已经完成，执行器适配层还需确认运行状态并结合传感器判断。原始 Grbl 接口与本方案的任务 JSON 是两层协议，不能直接混用。[Grbl 官方接口文档](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Interface)

### 3.3 必须实现的互锁

- 未回零/坐标不可信时禁止自动取放。
- E 未处于完整收回的运输位时，禁止 X/Z 运动。
- 已有盒子在外或托盘被占用时，拒绝新取盒任务。
- 对接位之外禁止 E 伸出；所有目标坐标经过行程范围检查。
- 取物时 X/Z/E 静止，用户确认手离开操作区后才允许回柜；首版为有人值守演示。
- 限位异常、传感器矛盾、阶段超时、通信丢失均停止继续执行；故障不能直接标记为完成。
- 实体急停结合垂直轴防坠设计。软件暂停不是实体急停的替代。
- 断电、急停或运动中断后进入 RECOVERY_REQUIRED。先人工检查盒子是否横跨柜格和托盘，再决定恢复路径；不可盲目先回零。

## 4. 取件、回件与状态模型

### 4.1 取件流程

1. 用户从网页或语音选择零件；后端解析到唯一盒号、柜格。
2. 校验设备已就绪、托盘为空、盒子在库、无其他未归还盒；创建任务并锁定设备及盒格。
3. E 确认位于运输位；X/Z 移动到标定柜格坐标。
4. E 伸出对接，舵机闭合拉钩，E 将盒子拉到托盘。
5. 验证 E 已收回且盒子完全到托盘，否则停止并报告阶段故障。
6. X/Z 将托盘送到固定取物口并停止。
7. 后端将盒位置改为 PRESENTED，任务完成；界面显示“B03 已送达，可取用”。

### 4.2 回件流程

1. 用户取用结束，点击/说“放回当前盒”，并确认操作区已让开。
2. 校验当前盒仍在托盘，原柜格保留给该盒；禁止现场把其他盒子放进其保留格。
3. E 保持收回，X/Z 返回原柜格。
4. E 推入盒子，确认对接深度和就位传感器，打开拉钩，空载退回。
5. 确认 E 收回、托盘为空；后端将盒位置改为 STORED，解除保留状态。
6. 托盘返回停靠位，记录任务完成。

### 4.3 三类状态要分开

```text
设备：UNHOMED → HOMING → READY → BUSY → READY
异常：任意执行状态 → FAULT / RECOVERY_REQUIRED

盒子：STORED → IN_TRANSIT → PRESENTED → IN_TRANSIT → STORED
异常：位置不能确认时 → UNKNOWN

任务：QUEUED → RUNNING → SUCCEEDED / FAILED / INTERRUPTED
```

P0 可不开放真正的等待队列：设备忙就拒绝新请求。一个取件任务送达即成功，但整个设备仍因“已有盒在外”而限制下一次取件，允许查询和回件。

物理操作中断时不能把数据库事务回滚解释为盒子已回到原位。保留最后确认位置和失败阶段，标为待恢复。

## 5. 后端、界面与语音

### 5.1 最小软件栈

建议使用团队最熟悉的 Web 技术。没有既有项目时可采用 Python 后端 + SQLite + 单页 Web 界面；运动放在 MCU，语音识别运行在 PC 或通过已有服务完成。

界面保留四个区域：

1. 零件搜索、名称与别名编辑、取件按钮。
2. 与实物一致的 2 × 3 柜格图：盒号、零件名、位置状态。
3. 当前任务：识别文本、目标盒、执行阶段、成功/故障信息。
4. 当前取物口：盒号、回件按钮、手动恢复入口。

工程调试页面另放回零、单轴点动、坐标标定和传感器状态。普通用户只看到取用过程。

### 5.2 最小数据结构

| 对象 | 字段 |
|---|---|
| parts | id, name, aliases；首版每盒对应一个品类 |
| slots | id, row, column, x_mm, z_mm, e_dock_mm |
| boxes | id, part_id, home_slot_id, location_state, last_confirmed_location |
| tasks | id, request_id, action, box_id, status, phase, error, created_at, finished_at |
| task_events | task_id, sequence, phase, sensor_snapshot, timestamp |
| device_config | 回零参数、行程、速度、加速度、取物口坐标、标定版本 |

约束：同一柜格只绑定一个盒子；同一设备只运行一个任务；同一个 request_id 不重复执行。任务完成后再更新“已送达/已归位”，命令 ACK 仅表示已接收。

### 5.3 建议接口

```text
GET   /parts?query=...
PATCH /parts/{id}             编辑名称和别名
GET   /cabinet                柜格、盒子与当前设备状态
POST  /tasks                 action=FETCH/RETURN, box_id, request_id
GET   /tasks/{id}             查询实际执行阶段
POST  /voice/interpret        返回文本、意图、候选盒、是否需用户选择
GET   /device/status
POST  /device/home            仅在满足恢复条件时允许
```

实时进度采用 WebSocket/SSE；若团队实现不熟悉，短间隔轮询已足够支持六格 Demo。

串口自定义任务例：

```json
{"type":"command","task_id":"T001","cmd":"FETCH","slot_id":"S03","config_version":1}
{"type":"ack","task_id":"T001","accepted":true}
{"type":"event","task_id":"T001","seq":2,"phase":"BOX_ON_TRAY"}
{"type":"result","task_id":"T001","success":true,"location":"PICKUP"}
```

MCU 用配置表将 slot_id 转成坐标。PC 与 MCU 标定版本不一致时拒绝动作。重复 task_id 返回当前状态；断线后查询，禁止盲目重发运动命令。MCU 重启后即使丢失去重缓存，也要因未回零/待恢复而禁止直接执行旧任务。

### 5.4 语音边界

固定支持四类指令：

- “拿 M3 螺母” → FETCH，唯一匹配到盒子。
- “拿三号盒” → FETCH B03，支持数字别名。
- “放回当前盒” → RETURN 当前已送达盒。
- “杜邦线在哪” → QUERY，返回柜格和盒状态。

流程：按住说话 → 语音转文字 → 动作及零件名称抽取 → 数据库匹配 → 业务校验 → 创建任务。

首版只需词典、别名与模板匹配。若使用大模型，把输出限制为动作枚举和候选零件 ID，再由后端校验；模型不得产生可直接执行的电机坐标或任意命令。

“拿螺丝”同时匹配 M3/M4 时展示两个候选，让用户选；识别失败就显示转写文本并允许修正。第一次 Demo 可以统一显示“即将取 B03”确认，降低噪声环境下的误触发。

语音识别实际成功是语音功能的验收条件。预设文本按钮只作备用输入，不能把它描述成现场语音识别。断网影响语音服务时，网页取放仍应可运行。

## 6. 48h 范围取舍

| 等级 | 内容 | 完成标准 |
|---|---|---|
| P0 必做 | 二维阵列定位 | 至少 2 × 2 格实际寻址，目标 2 × 3 |
| P0 必做 | 自动取盒及回盒 | 完整拉上托盘、送到取物口、推回原格 |
| P0 必做 | 位置和动作验证 | 回零、E 收回、托盘到位、回柜确认、超时处理 |
| P0 必做 | 后端持久化 | 零件名/别名、盒号、固定柜格、位置状态、任务日志 |
| P0 必做 | 网页入口 | 搜索、取件、回件、实时阶段与故障显示 |
| P0 必做 | 有限语音控制 | 至少三种零件名称的取件及“放回当前盒” |
| P0 必做 | 运行约束 | 单盒互斥、重复请求去重、失败不报成功、实体急停 |
| P1 余量再做 | 语音播报、灯效 | 与实际状态一致 |
| P1 余量再做 | 手工库存数量 | 用户确认增减，不从盒子存在推断零件数量 |
| P1 余量再做 | 盒子二维码核验 | 用于允许用户整盒拿走后的身份核对 |
| P2 后续 | 多盒在外、动态库位 | 要增加身份核验、缓存位置和调度规则 |
| P2 后续 | 自动称重计数、视觉识别 | 另行验证精度与适用范围 |
| P2 后续 | 传送带、手机 App、多人权限 | 本次无需增加这些系统 |

托盘存在传感器只能确认有盒，不能证明它是 B03。因此 P0 规定盒子留在托盘上，且只有一个盒在外。若演示要求整盒搬离设备，就必须增加“归还时确认盒号”的流程，二维码可作为后续实现。

## 7. 四人分工与进度门槛

分工：A 机械/加工；B 电控/固件；C 后端/通信；D 界面/语音/演示。并行由团队成员执行，机械与电控应共同负责取放机构验收。

| 时间 | A 机械 | B 电控 | C 后端 | D 交互 | 必须交付 |
|---|---|---|---|---|---|
| H0–H2 | 确认盒子、拉钩和托盘空间 | 确认现成模组与接口 | 定义状态和串口协议 | 确定页面和演示用零件 | 冻结范围、盒格编号、接口契约 |
| H2–H8 | 单格样机、手动拉推验证 | E 轴及舵机、传感器 | 数据表、任务互斥、模拟设备 | 柜格页面、麦克风采集验证 | 单格机械取放能成立 |
| H8–H16 | 柜体及 X/Z 装配 | 回零、单轴点动、限位 | 串口接入、日志、去重 | 页面接真实后端、语音匹配 | 单格电动取回连续 10 次 |
| H16–H24 | 全部柜格校准 | 完整取放状态机 | 真实任务回执更新状态 | 网页端到端取回 | 至少两个不同柜格真实闭环 |
| H24–H32 | 修正卡顿、拖链/布线 | 多格稳定性及故障处理 | 重连与恢复、持久化核对 | 语音接入同一任务接口 | 语音真实取盒和回盒 |
| H32–H40 | 稳定性修整 | 连续循环及异常验证 | 修复状态不一致 | 提示、演示脚本、录像 | 功能冻结，完成验收记录 |
| H40–H48 | 固定结构及备用件 | 不再改运动架构 | 仅修阻断故障 | 彩排、讲解、备用输入 | 可复现演示与备份视频 |

硬门槛：

- **H8**：单格拉出/推回仍不顺畅，立即修改盒接口和过渡面，暂停外观加工。
- **H16**：单格自动取回不稳定，削减到 2 × 2，并缩小重量与速度范围，保留完整闭环。
- **H24**：必须有真实硬件端到端流程，不能只有模拟器与独立电机测试。
- **H32**：停止增加新功能，优先修复卡盒、脱钩、状态错误和识别歧义。

若到最后仍只能人工把盒子放上托盘，应如实称为“定位与输送原型”，不能宣称自动取放已经完成。

## 8. 验收与演示

### 8.1 验收目标（待实测）

- 六个目标柜格各完成至少 3 次完整取回循环；另外进行至少 10 次混合柜格连续循环，记录干预次数、卡盒和错盒。
- 最终彩排连续 10 次不需要人工扶盒或纠偏；未通过时优先修机械对接，不能只补界面动画。
- 起始速度目标：单次从确认取件到送达 15–30 秒；以实际行程与承载测试调整，不把目标写成实测结果。
- 3 种零件名称各试 3 次语音取件，另外测试回件和一个有歧义的名称；记录识别正确、候选选择及失败次数。
- 重复点击/相同 request_id 不产生第二次物理动作。
- 当前盒未归还时，取下一盒被明确拒绝。
- 模拟拉空、未收回到位或回柜未确认时，系统不继续运输、不显示完成。
- 串口断连、设备重启后界面进入待恢复，盒子状态不被自动重置成在库。
- 实体急停能停止动作；复位后需明确恢复流程，不自动续跑。
- 后端重启后仍保留零件名称及映射；若执行中断，保留未决任务并要求核对物理位置。

计时拆分语音识别耗时与机械运输耗时，便于知道应该优化哪里。用运行记录描述演示稳定性，不能将少量样机测试当成产品可靠性认证。

### 8.2 约三分钟演示脚本

1. 15 秒：说明小零件多、位置难记、归还易乱的使用问题。
2. 20 秒：展示六格实体柜与对应管理界面，介绍盒号和零件名称映射。
3. 40 秒：说“拿 M3 螺母”，界面显示识别及匹配结果；真实机构取盒、送达。
4. 20 秒：取出一颗零件，展示盒子仍在托盘上，以及系统的已送达状态。
5. 35 秒：说“放回当前盒”，确认操作区已让开，机器回到原格完成归位。
6. 25 秒：展示歧义选择或重复请求防护中的一个真实能力。
7. 25 秒：展示操作日志，说明已经完成的能力和下一步扩展。

演示顺序以现场机械耗时调整。准备真实成功流程录像及网页备用入口，明确说明何时用了备用方式。

## 9. 第一小时即可分派的任务

1. 找到六个相同盒子，测尺寸、含物料重量和手动抽拉阻力，拍照记录接口。
2. 在纸上画出柜格—托盘侧剖面，确认抽出全过程的支撑和完全退出后的空间。
3. 用一个柜格、一个托盘和拉钩做单格样机；取出与放回都验证后再复制。
4. 软件建立 B01–B06、S01–S06 和三种演示零件，创建网页按钮到模拟设备的任务链路。
5. 固件与后端共同确定 task_id、ACK、phase、result、error 的含义，按上面的状态模型实现。
